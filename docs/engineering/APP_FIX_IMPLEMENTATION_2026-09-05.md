## 3. T1 — 다이어리 상세 데이터 덮어쓰기 차단

### 원인·변경 대상

- 같은 날짜·구조화 카테고리의 기존 기록을 자동 갱신하지만, 저장 후 상세 입력은 기본값으로
  초기화되고 접힌다. 저장 버튼은 계속 활성화되어 두 번째 저장이 첫 기록을 덮어쓸 수 있다.
- `apps/mobile/src/contexts/diary/ui/DiaryEntryScreen.tsx`
- 같은 디렉터리의 `DiaryEntryScreen.logic.ts`, `DiaryEntryScreen.formRules.ts`,
  `DiaryEntryActions.tsx`, `DiaryEntryScreen.test.ts`.

### 구현 방법

1. 편집 대상 식별자를 반려동물·날짜·카테고리·기록 ID로 명확히 관리한다. 기존 상세 기록을
   수정할 때는 저장된 detail, 컨디션 점수, 시각을 불러오며 루틴 기본값으로 대체하지 않는다.
2. 신규 초안, 기존 기록 편집, 저장 완료 상태를 분리한다. 기존 기록은 불러온 값과 현재 입력의
   변경 여부로 저장 가능 상태를 결정하고, 변경 없는 재저장은 mutation을 호출하지 않는다.
3. 상세 폼이 접힌 저장 완료 상태에서 숨겨진 기본값을 제출할 수 없도록 버튼과 저장 핸들러를
   함께 보호한다. 재편집을 열면 마지막 저장값을 표시한다.
4. 목록 재조회나 루틴 갱신이 사용 중인 초안을 덮어쓰지 않도록 초기화 효과를 제한한다.
   날짜·반려동물 전환 시 다른 대상에 편집 상태가 적용되지 않도록 경계를 유지한다.
5. 하루 한 구조화 기록이라는 기존 계약과 체크리스트 기록의 다이어리 승격을 유지한다.
   메모·사진의 하루 복수 기록, 과거 날짜, 역할별 수정 권한, 오프라인 재시도 ID도 유지한다.
6. 실패하면 초안·시각·대상과 재시도 정보를 보존한다. 성공한 경우에만 저장 기준값을 갱신한다.

### 개발 검증

- [x] 식사 50g 제공/35g 섭취·식욕 저하 재저장 시 update 0회: 핸들러 회귀 테스트 통과.
- [x] 기록 재편집·한 필드 수정 시 나머지 값 보존과 update 횟수: 자동 검증 통과.
- [x] 물·산책·배변·컨디션 상세 보존 및 체크리스트 승격: 자동 검증 통과.

## 5. T3 — 프리뷰 반려동물별 케어 상태 분리

### 원인·변경 대상

- `useCareSetupState`가 단일 로컬 설정을 공유하고 프리뷰의 `livePetId`는 모두 null이다.
  선택 반려동물을 바꿔도 이전 반려동물의 케어·투약 일정이 보인다.
- 이는 **프리뷰 로컬 상태 결함**이다. 실계정 간 데이터 누출로 판정한 것은 아니다.
- `apps/mobile/src/contexts/care/ui/useCareSetupState.ts`, `careSetupLocalState.ts`,
  `useCareSetupState.test.ts` 및 `apps/mobile/src/presentation/PawBloomShell.tsx`.

### 구현 방법

1. 셸에서 실제 선택값 `activePet.id`를 훅에 명시적으로 전달한다.
2. 프리뷰 설정을 `Record<petId, ActiveCareSetup>`으로 분리하고 선택 ID의 설정만 반환한다.
   처음 선택한 반려동물은 빈 설정을 사용한다. 전환마다 전체 상태를 초기화하지 않는다.
3. 저장 대상 ID를 작업 시작 시 고정하고 함수형 상태 갱신으로 해당 반려동물만 변경한다.
   다른 반려동물의 질환·플랜·일정과 같은 반려동물의 기존 일정은 보존한다.
4. 실계정 query/mutation의 기존 계정·펫 범위와 응답 지연 보호는 유지한다.
   DB 모델·RLS 변경이나 프리뷰 영구 저장은 이 수정에 포함하지 않는다.
