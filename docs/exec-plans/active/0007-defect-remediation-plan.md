## Phase A — P1: 출시 블로커

- [ ] A1. **시간대 RLS 정정(P1 1·2)** ※**사용자 승인 필요 — 스키마·보안 변경**. `timezone('Australia/Sydney', ...)` 하드코딩 6개 마이그레이션을 정정한다. 권고안: 서버가 `occurred_at`에서 날짜를 재유도하지 않고, 클라이언트가 보낸 `entry_date`가 `occurred_at ± 24h` 범위에 있는지만 검증(로컬 달력은 기기가 권위). pet_sitter '오늘' 제한도 같은 기준으로 완화. 수용 기준: 서울 23:30·시드니 09:00·뉴욕 22:00 각각에서 다이어리·투약 저장 성공, 기존 무결성 테스트 통과. 적용은 `supabase db push` — 실행 주체는 사용자.
- [x] A2. **오프라인 저장 정지 해소(P1 3·4)** — QueryClient 기본값에 `networkMode: "always"`(queries·mutations). 아웃박스 적재가 `mutationFn` 안에 있으므로 pause되면 큐가 비고, paused 쿼리는 빈 상태로 위장된다. `verify:offline`에 회귀 가드 추가. 커밋 `2a5fe2a`.
- [ ] A3. **개인정보처리방침 게시본 정정(P1 5·6)** ※**사용자 입력 필요**. `[EFFECTIVE_DATE]`(시행일 결정), `[SUPPORT_EMAIL]`(현재 인앱 지원 주소와 일치시킬 것), `[SUPABASE_REGION]`(실제 프로젝트 리전) 치환 + 프런트매터가 렌더되지 않는 게시 위치로 이전(GitHub Pages 등). 수용 기준: 링크 대상에 자리표시자 0건, 내부 메타데이터 비노출. 앱스토어 제출 선결 조건.

## Phase B — P2: 저장·알림 무결성

- [x] B1. **펫 삭제 시 알림 취소** (`c0ab5e3`) — `authPetMutations` 삭제 경로에서 해당 펫의 예약 알림을 취소(투약·식사). 수용 기준: 삭제 후 예약 알림 0건.
- [ ] B2. **투약 알림 토글 전 펫 복원** — 토글 on 시 활성 펫만이 아니라 스케줄이 있는 모든 펫을 재예약. 수용 기준: 2펫 환경에서 off→on 후 양쪽 알림 복원.
- [ ] B3. **루틴 미로드 상태로 알림 재예약 금지** ※저장 덮어쓰기 차단만 완료(`c4a9931`) — `reminderScheduling`이 루틴 쿼리 `status !== "ready"`면 재예약을 건너뛴다. 저장 경로도 기본값 덮어쓰기 방지(로드 실패 시 저장 차단 + 재시도). 수용 기준: 오프라인 진입 후 기존 알림 유지.
- [ ] B4. **용량 필수 규칙 클라이언트 정렬** — `dosageLabel`을 폼 검증에 추가(서버와 동일 규칙), 인라인 오류 문구. 수용 기준: 빈 용량으로 저장 시 원인이 폼에 표시.
- [ ] B5. **오프라인 재전송 날짜·시각 보존** — 큐 적재 시점의 `entry_date`/`occurred_at`을 페이로드에 고정하고 replay가 재계산하지 않게 한다. 수용 기준: 자정 경과 후 재전송해도 원래 날짜·시각 유지.
- [x] B6. **연타 가드** (`e89b326`) — 케어 아젠다 상태 버튼에 in-flight 잠금(체크리스트 `pendingKeys` 패턴 재사용). 수용 기준: 연타 시 오류 배너 미발생.
- [ ] B7. **스케줄 시각 보존·창 필터** — '오늘 기록으로 불러오기'가 스케줄의 복용 시각을 유지하고, 오늘 적용되지 않는 일정에는 버튼을 노출하지 않는다.
- [ ] B8. **미래 날짜 차단** — 다이어리 달력·반려동물 생일 입력에 미래 제한.
- [ ] B9. **입력 유실 방지** — 투약 편집 중 상태 버튼 입력 초기화 차단, 다이어리 초안이 있는 탭 전환 시 확인 또는 초안 보존.
