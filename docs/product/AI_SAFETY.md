# AI 안전 정책

PawBloom AI는 수의사가 아니라 기록 요약 도구다.

## 허용

- 최근 식사, 물, 배변, 약, 컨디션 기록을 요약한다.
- 누락된 기록을 알려준다.
- 반복되는 패턴을 조심스러운 표현으로 설명한다.
- 수의사에게 물어볼 질문을 제안한다.
- 한국어 또는 영어 기록을 기반으로 영어 병원 리포트 요약을 만든다.

## 금지

- 질병을 진단한다.
- 약을 처방한다.
- 약 용량 변경을 추천한다.
- 병원 방문이 필요 없다고 말한다.
- 상태가 응급인지 아닌지 단정한다.
- 특정 질병 가능성을 확정적으로 표현한다.

## 필수 고지 문구

모든 AI briefing과 vet report에는 아래 고지문을 포함해야 한다.

영문 출력 문구:

```text
This is a record-based summary, not a diagnosis. Contact a veterinarian for medical decisions.
```

한국어 UI 문구:

```text
이 내용은 진단이 아니라 기록 기반 요약입니다. 의학적 판단은 수의사에게 문의하세요.
```

## 표현 원칙

- "기록상", "반복해서 기록됨", "수의사에게 문의할 질문"처럼 관찰 중심으로 표현한다.
- "원인은", "진단은", "치료는", "응급입니다"처럼 의료 판단으로 보이는 표현은 피한다.
- AI output은 항상 사용자가 입력한 기록의 범위 안에서만 설명한다.

## 아바타·공동 추억 확장 (2026-10-18 목표)

- 사진 생성은 외형을 닮게 하는 창작 처리다. 사진으로 질병·감정·통증을 판정하는 기능을 추가하지 않는다.
- 캐릭터의 표정·배회·작은 반응은 연출이다. 실제 아이의 건강·배고픔·행복 측정으로 표현하지 않는다.
- 기록이 없다는 이유로 캐릭터를 아프게 하거나 사라지게 하지 않는다.
- 투약 완료·과한 활동을 보상 조건으로 삼지 않고 건너뜀·부분 복용도 솔직히 기록하게 한다.
- 공동 추억의 이야기·연출 문구·다른 아이 기록을 clinical briefing/report 근거에 자동 포함하지 않는다.
- 현재 템플릿 요약과 향후 생성형 AI를 구분한다. 아바타 생성 추가가 LLM 건강 브리핑 도입을 뜻하지 않는다.
- 생성 실패·전송 대기·동기화 실패를 돌봄 완료·건강 이상·가족 공유 완료로 바꾸어 표현하지 않는다.

## 사진→캐릭터 생성 (2026-11-01)

- 제공자는 OpenAI API(Responses API, 모델 `gpt-6.1-sol`, reasoning effort `high`)다. 서버 함수 `generate-pet-avatar`만 호출하고 키는 서버 비밀 `OPENAI_API_KEY`에만 둔다. 앱은 키를 갖지 않는다. 요청은 `store: false`로 보내 OpenAI에 응답 상태를 저장하지 않는다(남용 모니터링 로그는 OpenAI 정책상 최대 30일).
- 입력은 사용자가 동의 문구(`avatar-ai-2026-11-01`)에 동의하고 직접 고른 사진 1장이다. 모델은 외형(털 색·무늬·눈 색·귀·털 길이·체형·꼬리·얼굴 무늬·목걸이)을 기존 캐릭터 옵션 중에서 고르기만 한다. 이미지 생성 모델은 쓰지 않는다.
- 금지: 사진으로 건강·감정·통증·나이·품종을 판정하거나 표시하는 것, 사람·배경을 묘사하는 것, 제공자 응답 원문을 사용자에게 보여주는 것.
- 사진과 프롬프트·응답 원문은 DB에 저장하지 않는다. 전송 전에 사진 메타데이터(위치 등)를 지운다. 생성이 끝나면 원본 사진 객체를 즉시 삭제하고(중간에 멈춘 생성은 늦어도 2시간 안에) 모델명·토큰 사용량·중단 사유·요청 ID만 남긴다.
- 제공자가 거부(refusal 항목·`content_filter`·이미지 정책 위반)하거나 고양이·개를 찾지 못하면 EN/KO 오류 코드로 알리고 기존/기본 캐릭터를 유지한다. 한도는 사용자당 직전 24시간 동안 10회다.
