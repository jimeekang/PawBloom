# PawBloom 포지셔닝 및 기능 전략

상태: 2026-10-18 사용자 선택을 반영한 목표 방향. 제공 중인 기능 목록이 아니다.
범위·동작 정본은 [PRODUCT_SPEC.md](PRODUCT_SPEC.md), 구현 순서는 [0009](../exec-plans/active/0009-avatar-care-memories-implementation.md)다.

## 제품 포지션

> 내 아이를 닮은 캐릭터들이 함께 지내는 우리 집에서, 가족이 실제 돌봄과 추억을 쌓는다.

기존 가족 케어 기록·병원 전달 가치를 유지하면서 일상의 애착과 재방문 경험을 강화한다.
사진을 자주 찍고 가족·연인과 돌봄을 나누는 보호자를 초기 대상으로 삼는다.
건강 관리가 잦은 보호자는 캐릭터 탐색 없이 오늘 케어에서 바로 기록한다.

핵심 흐름은 **사진 → 내 아이 캐릭터 → 여러 아이 공간 → 실제 케어 → 공동 추억 → 기록 브리핑**이다.
가상 캐릭터를 별도로 먹이는 숙제를 만들지 않고 실제 기록 한 번을 화면의 반응과 연결한다.

## 첫 버전의 세 축

1. 내 아이 아바타: 한 가지 2D 스타일, 닮은 특징, 결과 확인·재시도, 기존 아이에도 추가.
2. 실제 케어: 기존 루틴·투약·기록·알림·오프라인과 전체 아이 일정.
3. 공동 추억: 가족 작성·복수 아이 태그, 전체 한 번·아이별 연결 표시.

우리 집 / 오늘 케어 / 추억 / 더보기와 아이별 케어 / 추억 / 프로필을 사용한다.
드래그·짧은 배회·작은 반응과 목록 선택·움직임 줄이기를 제공한다.
배치는 개인 설정이며 케어·추억 데이터를 가족과 공유한다.

## 기존 가치와 권한

- 프로필 사진·종별 기록·투약/식사 알림·가족 기여·계정 경계·삭제를 유지한다.
- 현재 템플릿 기록 요약을 이어 쓴다. 새 LLM·사진 진단을 제공한다고 약속하지 않는다.
- 병원 리포트는 사용자 확인·sanitized payload·만료 링크를 유지한다.
- 캐릭터를 바꿔도 실제 아이와 기록 연결은 유지한다.
- 복수 태그는 같은 활성 owner/caregiver 집합의 아이끼리만 허용한다.
- pet_sitter 권한을 전체 기록·추억 권한으로 넓히지 않는다.
- 영/한·호주 우선 방향을 유지하고 기타 동물은 기본 캐릭터·기록을 쓴다.

## 보상과 신뢰

보상은 작은 반응과 함께한 날·추억으로 시작한다. 체크 횟수를 건강 점수로 표현하지 않는다.
캐릭터 감정은 연출이다. 기록 누락·복약 건너뜀을 벌주거나 운동량·투약 경쟁을 만들지 않는다.
케어는 아이별로 구분하며 공동 추억을 의료 사실로 자동 변환하지 않는다.
의료 표현의 정본은 [AI_SAFETY.md](AI_SAFETY.md)다.

## 수익화와 범위

Free/Plus/Family 구조를 유지하며 다중 아이·가족 참여가 핵심 경험을 막는지 공개 베타 전에 결정한다.
무료 v1은 [RELEASE.md](../engineering/RELEASE.md)의 권장안이며 서버 권한을 해제하는 명령이 아니다.
새 과금·상점·재화·구독 연동은 이번 범위 밖이다.
3D·미니게임·랭킹·교배·꾸미기·실시간 공동 이동·성격 챗봇·GPS·커뮤니티·보험·예약은 후속 후보다.

## 가치 검증

- 첫날: 캐릭터 적용 후 케어 또는 추억 한 건을 남길 수 있는가.
- 반복 사용: 둘째 주에도 실제 케어 기록과 가족 기여가 이어지는가.
- 품질: 닮음·입력 부담·캐릭터 선택 실수·보상만을 위한 허위 체크를 관찰한다.
- 보호자 10~15명, 2주 사용은 제안된 탐색 실험이다. 모집·실험 결과나 검증된 성공 수치는 없다.
- 기존 시장 분석은 작성 당시 근거로 보존하며 이번 방향의 수요 검증 완료 근거로 쓰지 않는다.
