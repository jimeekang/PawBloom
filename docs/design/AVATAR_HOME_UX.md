- 기준: 2026-10-18 채팅에서 선택한 방향. 구현 전 목표 사양이며 현재 화면의 검증 결과가 아니다.
- 범위: [제품 명세](../product/PRODUCT_SPEC.md), 구현: [0009](../exec-plans/active/0009-avatar-care-memories-implementation.md).
- 기존 기록·역할·오류 복구를 유지한다. 세부 시각 시안은 구현 전 선택하고 기존 token과 연결한다.

## 탐색과 화면 순서

| 화면 | 위에서 아래로 | 핵심 행동 |

기록+의 저장 전 대상 아이를 항상 표시하고, 여러 아이 케어를 무심코 일괄 완료하지 않는다.

## 사진과 생성

v1 생성 방식은 [CHARACTER_DESIGN](CHARACTER_DESIGN.md)의 생김새 빌더(파라메트릭 벡터 캐릭터)다. 아래 사진 기반 흐름은 보류된 이후 옵션이다.

촬영/앨범 → 대상 아이·선택 사진 확인 → 외부 생성 처리 안내/동의 → 처리 중 → 결과 확인 → 적용.
이름·종류 등 필수 기본값 외의 루틴/치료 입력을 캐릭터 생성의 선행 숙제로 강제하지 않는다.
기존 프로필은 그대로 사용하며 캐릭터 재생성 때문에 pet을 새로 만들지 않는다.
생성 중 뒤로 나가도 상태를 다시 볼 수 있고 실패 시 원본/기존 캐릭터를 유지한다.
권한 거부는 설정 안내·다른 입력을 제공하고 비어 있는 이미지로 성공 표시하지 않는다.
사진을 닮은 모습과 반복 동작의 일관성이 핵심이다. 질병·감정 판독으로 표현하지 않는다.

## 공간과 조작

- 첫 버전은 따뜻한 2D 공간 하나다. 가구 상점이나 꾸미기 조작을 넣지 않는다.
- 짧은 탭은 요약창, 긴 누름 뒤 끌기는 배치다. 배치 종료는 탭으로 처리하지 않는다.
- 배경 좌우 이동과 캐릭터 끌기를 구분한다. 좌표는 안전 영역 안으로 제한한다.
- 작은 배회·눈 깜빡임·앉기를 제공한다. 끌기·선택 중에는 배회를 멈춘다.
- 정지/위치 고정과 OS 동작 줄이기를 지원한다. 비활성 화면에서 모션을 돌리지 않는다.
- 겹친 아이도 이름 목록으로 선택한다. 접근성 사용자는 드래그 없이 아이 상세를 열 수 있다.
- 배치는 계정·기기별 개인 설정이며 가족의 실시간 공동 이동은 없다.
- 0마리: 첫 아이 등록. 생성 전/실패: 사진·기본 캐릭터. 1마리: 자연스러운 기본 배치.
- 아이가 많으면 좌우 공간을 확장하고 아이 목록을 유지한다. 6마리는 검증 표본이지 등록 한도가 아니다.

## 실제 케어

전체 케어에서 모든 접근 가능한 아이의 예정/기록을 모은다. 일부 로드 실패는 해당 아이의 재시도로 표시한다.
투약명·대상·시간·예정/완료/건너뜀/부분 복용을 구분한다. 수치는 캐릭터 애정/건강 점수가 아니다.
모든 입력·확인·저장 실패·재시도에서 아이와 날짜를 유지한다. A 편집 중 B를 열어도 A 초안을 B에 저장하지 않는다.
이전 날짜·사진·구조화 폼·루틴·투약 설정은 새 메뉴에서 계속 접근한다.
알림 진입은 대상 아이·일정을 열기만 한다. 로그인/권한/삭제 상태를 확인한 후 표시한다.

## 공동 추억

입력은 사진 또는 이야기, 날짜/시각, 함께한 아이, 공개 범위다. 작성자는 로그인 계정으로 결정한다.
동일 구성원 아이끼리 복수 태그하고 전체 한 번·아이별 연결로 표시한다.
공유 구성원이 달라 복수 태그가 불가하면 각 아이별 작성으로 복구할 수 있게 안내한다.
가족 작성자를 표시하고 탈퇴 작성자는 중립 이름으로 표시한다. 이메일을 불필요하게 공개하지 않는다.
기존 사진/메모는 출처를 구분해 표시하고 원래 편집 화면으로 보낸다.
현재 아이별 날짜당 사진 5장을 새 추억과 합산한다. 복수 태그 사진은 각 아이에게 계산한다.
상한 도달 시 저장 전에 대상과 사유를 안내한다. 새 과금 화면으로 유도하지 않는다.
오프라인/부분 실패는 전송 대기 초안을 유지하고 공유 완료와 구분한다. 첫 버전은 온라인 명시적 재시도다.

## 피드백·안전

실제 기록 저장 후 짧게 반응한다. 함께한 날과 추억 수는 축적된 사실로 표시한다.
queued/실패 상태를 서버 저장·가족 공유 성공으로 꾸미지 않는다.
기록이 없다고 캐릭터를 아프게 하거나 사라지게 하지 않는다. 투약 완료·과한 활동량을 보상 조건으로 삼지 않는다.
캐릭터 표정은 연출이며 실제 건강 판정이 아니다. [AI 안전 정책](../product/AI_SAFETY.md)을 따른다.
공동 추억에 포함된 pet 삭제는 해당 추억 전체에 영향을 준다는 확인을 제공한다.

- 생성 실패·업로드 부분 실패·일부 케어 로드 실패·초안·권한 회수·다른 계정 진입을 확인한다.
